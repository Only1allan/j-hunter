# Outbound

**This module deliberately contains no code that sends anything.** Submission is
manual, by design and by choice.

## Contents

| Path | What it is |
|---|---|
| `manifest.csv` | The application queue — one row per generated package, with an `applied_on` column you fill in by hand. Generated by `jobapp generate`, then owned by you. |

## Why manual

The session brief treats manual submission as a valid path *provided the tailored
outputs are ready to paste* — which is exactly what `output/` produces. Given that, an
auto-apply integration adds real risk (wrong resume to the wrong company, a half-filled
form submitted under your name, an application you cannot retract) in exchange for
saving a few minutes per job.

The applications themselves are also the KPI that matters, and they are worth looking at
before they go out. Reviewing each package is where a bad tailoring pass gets caught.

## Working the queue

```
company,role,apply_url,pay_score,match_score,package_dir,applied_on,response
```

Sort by `match_score` or `pay_score`, open `package_dir`, attach `resume.pdf` and
`cover-letter.pdf`, copy answers from `answers.md`, then record the date in
`applied_on`. `response` is there so the queue doubles as a tracker — and so the
`applied → response` ratio can eventually feed back into the match threshold.

## If this is automated later

The path is Greenhouse's and Lever's public application endpoints — the same APIs
`sources.py` already uses to *read* postings, which is why they were chosen as the
primary job source. Those APIs also return each posting's custom questions as
structured JSON, which is what makes the hard requirement implementable:

> escalate to manual review whenever the AI cannot answer a form question

Two rules any future implementation must keep:

1. **Never send without an explicit confirmation step**, unless the user has turned that
   off deliberately and knowingly.
2. **Append to the audit log before and after the call**, so a crash mid-flight cannot
   produce a silent double-application.

Browser automation for boards with no API is the step after that, and a larger one —
selectors break per-site, and discovering form questions visually makes the escalation
rule much harder to honour than it is with structured JSON.
